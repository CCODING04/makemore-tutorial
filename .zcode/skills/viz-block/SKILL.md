# viz-block：信息流内容可视化生成法

把教程 md 里的 text 图示块转成**页内可视化组件**（不是换容器装文本，而是生成真正的图形表达）。
设计基准是 chunk.html 视觉语法：**标题 + 语义分色节点 + 箭头/连线 + 图例 + 折叠原文 + 一致性校验**。

## 〇、核心原则（先读，三条铁律）

这三条每一条都对应一次真实的返工，违反任何一条 = 重做：

1. **可视化 = 生成图形表达，不是给文本换壳。** 把 text 块塞进一个带边框的 div、内容原样是等宽文本——这不叫可视化，用户会直接打回。组件里必须没有"原来的字符画"，只有节点/连线/色块/注释。
2. **理解内容后 authored 生成，禁止写解析器自动转换。** 自动解析（正则猜哪行是节点）产出的东西"与原文一致但没有理解含义"：无标题、无图例、清一色颜色、把组成结构画成顺序链；且质量门收再多轮仍会误转散文/时间线/矩阵。正确路径：**人读原文 → 按语义手写 viz JSON**。自动机制只保留两种无语义负担的形态：横幅输出块→运行输出卡、空格对齐表格→HTML 表格。
3. **先判关系语义，再选组件类型。** 拿到原文先问：这是**线性流程**（A 做→ 完 B 接着做）？**组成结构**（X 由 A、B 两部分组成）？**树状层级**？还是**重复/堆叠**（×N 次）？类型选错，表述再对也是错的（如把"Block 由①②组成"画成三个节点的竖链）。对应：flow / panel / tree / stack 指示器。

## 一、判断哪些块该转

**该转**（信息流内容）：
- 流程 / 管线：`A ──→ B ──→ C`、垂直 `内容 │ ▼` 堆叠
- 结构框图：`┌─┐ Transformer Block │…└─┘` 这类盒子图（转成 flow 节点）
- 树状结构：父子层级 ASCII（转 `type=tree`）
- 对齐表格：空格对齐的对比列（构建期自动转 HTML 表格，无需 viz）

**不转**（保持现状）：
- 脚本运行输出（`═══ 标题 ═══` 横幅块 → 构建期已自动转「运行输出」卡片）
- 日志（`[INFO] …`）、对话示例、矩阵/数值数据、散文段落、单箭头句子

## 二、生成方法（固定流程）

1. **定位原文块**，逐字复制其完整文本（含缩进与对齐空格）。
2. **原文块保持不动**，紧跟其后新增 ```` ```viz ```` 围栏块，JSON 结构：

```json
{
  "type": "flow",              // flow=流程/管线；tree=树状结构；panel=模块面板（PPT 图示风）；highway=主干道+分支并入（残差）
  "title": "组件标题",          // 必填：概括这组信息的名字
  "subtitle": "一句话副标题",    // 推荐：补充语境
  "src": "<原文块的逐字副本>",   // 必填：一致性校验依据，逐字一致（含空格/换行）
  "rows": [                    // type=flow 用
    {"chain": [["节点文本", "类型"], ...]},          // 水平链（类型省略默认 mid）
    {"node": ["节点文本", "类型"], "note": "← 注释"} // 垂直节点（可带注释）
  ],
  "levels": [                  // type=tree 用：顶层在前，每层 [文本, 类型] 数组
    [["根", "output"]],
    [["左", "mid"], ["右", "mid"]]
  ],
  "container": "外框名",        // type=panel 用：可选容器框标签
  "modules": [                 // type=panel 用：子模块卡（结构/组件图优先用 panel 而非 flow）
    {"badge": "①", "kind": "op", "name": "模块名", "desc": "一句话职责",
     "tag": "Multi-Head Self-Attention", "tagKind": "op", "icon": "🔗"}
  ],
  "stack": {"label": "Block 重复 n_layer 次", "segments": ["op", "green"], "count": 3},
  "trunk": {"from": "输入", "to": "输出"},   // type=highway 用：主干道两端
  "branches": [                              // 主干垂下的子层盒（取样↓/写回↑双线 + ⊕ 自动绘制）
    {"label": "+sa(·)", "kind": "op", "note": "Self-Attention · 自注意力"}
  ],
  "formula": ["x", "x + sa(x)", "⋯", "输出"],  // 可选：底部公式条（逐层累加链）
  "note": "⊕ = 加法并入点",
  "legend": {"input": "…", "op": "…", "mid": "…", "output": "…", "green": "…", "trunk": "主干道"}  // 可选：覆写图例文案
}
```

**类型选择**：线性流程 → `flow`；树/层级 → `tree`；**结构/模块组成（"X 由 A、B 组成"、盒子图）→ `panel`**——PPT 图示风：容器框内子模块卡（圆形徽章 + 名称 + 职责 + 彩色代码标签 + 图标），重复/堆叠用 `stack`（双色条缩略块 ×N + ↓ + ⋯）形象表达；**主干道 + 分支加法并入（残差/旁路）→ `highway`**——横主干贯通（from → to），分支下垂做完全部 ↑ 加回（⊕ 汇合点自动绘制）。遇到现有类型都不贴合的新拓扑：**新开类型，不要硬塞进 flow**。

3. **语义分色**（必须按内容属性选类型，不许清一色）：

| 类型 | 颜色 | 语义 |
|---|---|---|
| `input` | 灰底描边 | 输入 / 字符 / 原始数据 |
| `op` | 蓝实底白字 | 变换 / 操作 / 通信（attention） |
| `green` | 绿实底白字 | 计算 / 第二类并列模块（FFN 等） |
| `mid` | 蓝浅底 | 中间结果 / 传递 |
| `output` | 红实底白字 | 输出 / 最终结果 |

4. **图例**：自动按用到的类型生成；同类节点不要重复出现；有更贴切的叫法用 `legend` 覆写。
5. **构建验证**：`python tools/build_site_lite.py --force`
   - 无 `⚠️ viz 原文不匹配` → 通过；出现告警 = `src` 与原文有出入（多半是空格/换行），逐字修正。
6. **浏览器验收**：组件有标题头、节点按语义着色、图例齐全、底部「原始文本」折叠项、无黄色过期横幅。

## 三、一致性（staleness）机制

- 构建期把 viz 的 `src` 与**紧邻其前的原文块**逐字比对：一致 → 原文块被组件内折叠原文取代（不丢内容）；不一致 → 构建日志告警 + 页内黄色「原文已变化，请重新生成」横幅。
- 因此：**viz 必须紧跟其原文块**，中间不能插其它块。
- 修改了已有 viz 对应的原文后，必须同步更新该 viz 的 `src`（以及节点内容，如语义有变）。

## 四、质量标准（对齐 chunk.html）

- [ ] 有标题（+推荐副标题），不裸奔
- [ ] 节点 ≥ 2 种语义颜色，颜色由内容属性决定
- [ ] 图例齐全且文案准确
- [ ] 原文进「原始文本」折叠项，页面无过期横幅
- [ ] 树结构有真实连线（plot.js SVG 绘制），不是字符画
- [ ] 组件在明/暗两主题下均可读（颜色全部走 CSS 变量）

## 六、避坑清单（历史踩坑实录 → 症状 → 正确做法）

本节是真实返工记录。下次做同类事情先扫一遍这张表，能直接抓住重点。

| # | 踩过的坑 | 症状（用户原话/表现） | 正确做法 |
|---|---|---|---|
| 1 | **换容器装文本**（第一版 out-card） | "你只是把 text 换了一个 div 块来装，UI 和样式并没有变" | 组件内不允许出现原字符画；原文进折叠项，正文只留图形元素 |
| 2 | **写解析器自动转换**（flow_widget 阶段） | "制作的非常简陋……没有理解需要表述的含义"；散文/时间线/矩阵被误转成色块 | 人读原文、按语义手写 viz JSON；保留 src 一致性校验防漂移 |
| 3 | **关系语义选错型**（盒子图第一版画成竖链） | "表述与原文一致但图形化太简陋，没有理解含义" | 组成结构→panel；线性流程→flow；树→tree；重复堆叠→stack 指示器（画出来，别写"×N"文字节点） |
| 4 | **缺标题/图例/分色** | 清一色蓝色节点裸奔，无上下文 | 每个组件必须有标题(+副标题)、≥2 种语义色、图例；这是 chunk.html 的三件套 |
| 5 | **src 与原文不一致** | 构建 `⚠️ viz 原文不匹配` 误报（多因空格/换行/全半角） | src 从 md 原文**逐字复制**（含缩进对齐空格），不要手打；改原文必须同步改 src |
| 6 | **viz 与原文块之间插了内容** | 锚定失败触发过期告警 | viz 必须紧跟其原文块；被自动转成表格的块同样可锚定（仍保持紧邻即可） |
| 7 | **图形化程度不够** | "按照做 PPT 图示的方式来表述更形象" | 结构类优先 panel 的富表达：容器框、圆形徽章、彩色代码标签、图标、堆叠双色条缩略块——对齐用户给的参考 HTML 水准 |
| 8 | 细节坑（工程） | 字体/重复/双渲染 | ① 代码块字体规则要落在 `pre` 上（Pygments 输出无 `<code>` 包裹，Windows 会落到 Courier New）；② 图例同类去重；③ tree 的折叠原文由 plot.js 生成，构建端不要重复输出；④ 组件同色贯穿：模块徽章、tag、堆叠条、图例必须同语义同色 |
