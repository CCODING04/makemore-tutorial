📌 这张图画什么

一个 32 层、d_head=128 的模型在做自回归生成：上方是已生成的序列（每格一个 token），下方两列是 MHA 与 GQA 各自 32 层的 KV Cache。每生成一个新 token：① 它的 K/V 追加进每一层的缓存；② 两列的条子同步变长——但 GQA 列永远是 MHA 的 1/4。显存随序列变长线性无上限，这是长对话 OOM 的根源。

🔖 符号与标识符

L=32Transformer 层数——每层都有独立的一份 K/V 缓存（图里每层一根条）
H_kvKV 头数：MHA 全量 32；GQA 分组共享压到 8（Llama-3 的做法）——KV 恰好 ÷4
d_head=128每个头的维度
S当前已生成的序列长度（动画逐帧推进的就是它，上限 2048）
系数 2K 和 V 是两个矩阵
bytes=2fp16/bf16 每元素 2 字节（int8 量化再省一半）

🧭 试一试

  • 按 |▶ 逐帧推进：两列条子同步变长，右侧数字实时跳——MHA 在 S=2048（满帧）时正好 1.0 GB，GQA 只有 0.25 GB
  • 盯住"÷4"徽章：任何时刻两列的比值都恒定——GQA 省的不是某一层而是每一层
  • 心算验证 S=2048：2×32×32×128×2048×1×2 字节 = 1.0 GB（MHA）/ 0.25 GB（GQA）——与列头读数对照
