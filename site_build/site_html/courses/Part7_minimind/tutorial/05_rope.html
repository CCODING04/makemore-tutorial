05 — 位置编码：让注意力认识顺序（learned PE → RoPE）

0. 本章地图
前置（你需要什么）自注意力公式与多头（02 章）、实验纪律（03 章：同 seed、控制变量、验证 ppl）。不需要任何 RoPE 先验
本章贡献（你获得什么）位置编码的完整故事：为什么必需 → 方案全景 → 旋转位置编码的推导与手算验证 → 完整实现 → 外推实验。配套脚本 05_rope.py（= 04 章全部代码 + 本章零件）
框架位置课程零件升级三部曲之一：05 位置（本章）→ 06 注意力 → 08 组装。所有现代 LLM（Llama/Qwen/minimind）的位置编码都在本章

🧭 问题清单第 ② 条：模型训练时只见过 340 个位置，推理时来了 512 长的输入会怎样？

1. 问题引入：注意力是个"词袋"

场景：把"猫咬狗"和"狗咬猫"喂给一个没有位置编码的 Transformer，它的输出完全相同。 这不是 bug，是注意力的数学性质——置换等变。看输出公式（单头）：

输出_i = Σ_j α_ij · v_j，其中 α_ij = softmax_j(q_i·k_j/√d)

q_i·k_j 是内容与内容的点积，公式里没有任何地方出现"j 在 i 前面还是后面"。把输入顺序打乱 （置换 π），每个 α_ij 的分子集合不变、求和顺序无关，输出就是原来输出的同序打乱：

输入 π(x) → 每个 token 的 q,k,v 按 π 重排 → 输出 = π(输出(x))   □

🔑 结论：不加位置信息的注意力是"词袋模型"——只数词、不认顺序。位置编码不是可选组件， 是让注意力变成语言模型的那块缺失器官。

2. 方案一览：补上位置感的四条路

方案 思路 代表 一句话评价
正弦位置表固定的 sin/cos 函数表加到 embeddingTransformer 原论文 (2017)不学习，靠设计
learned PE同样是表，但可训练GPT/BERT（02 章基线）本章 2 的"现状"，§3 看它的毛病
RoPE不加表，把位置"旋"进 q/k 里Llama/Qwen/minimind 全线本章主角
ALiBi（Attention with Linear Biases）不改向量，给注意力分数加线性距离惩罚BLOOM 系相对阵营，表达力上限低

先看清现状的问题，再看全景里为什么选 RoPE。

3. learned PE 的两个毛病，与 RoPE 的解法

3.1 现状：基线里的位置表

02 章基线的做法：x = token_emb(input_ids) + pos_emb(0…T-1)，其中 pos_emb = nn.Embedding(max_pos, hidden)——一张可训练的表，位置 i 查第 i 行。

毛病一：表长 = 视野，且是硬上限。 表只有 max_pos 行，位置超过表长连查都没得查 ——不是"效果变差"，是结构上无法计算。训练 340、推理 512 可以查（max_pos=1024），但 340~512 那些行从未被训练过——只是 normal(0, 0.02) 的随机初始化值。效果如何，§5 实验说话。

毛病二：它编码的是绝对位置。 位置 5 的向量永远是同一个学习结果。但语言理解常常只关心 相对距离——"的"跟它修饰的词隔几个字，比"的"在第几位重要得多。绝对编码下模型要在 每个位置上分别学会"距离 3 的修饰关系"（位置 5 学一遍、位置 50 再学一遍）。

3.2 RoPE 的核心思想与推导：只许旋转

对 q、k 各找一个位置注入函数 f(x, m)（m 是位置），要求：

目标：⟨f(q, m), f(k, n)⟩ 只依赖 (q, k) 的内容和 (m − n) 的差——相对性
约束：f 不能破坏向量携带的内容信息 → 只做正交变换 → 最简单的正交变换是二维平面旋转

把 q、k 限制在二维平面，f 取旋转角为 mθ 的旋转矩阵 R(mθ)。内积两行推完：

⟨R(mθ)q, R(nθ)k⟩ = qᵀ R(mθ)ᵀ R(nθ) k（转置移过去）
= qᵀ R((n−m)θ) k（旋转矩阵性质：R(a)ᵀR(b) = R(b−a)）
└──────── 只依赖 m − n ────────┘□

推导只有一行运算：旋转的正交性（R(a)ᵀ = R(−a)）自动送给我们相对性——设计目标和 §3.3 末性质清单里的 "性质②"是同一件事。用复数写等价且更直观：位置 m 的 q 乘 e^{imθ}，内积取实部 Re[q · k* · e^{i(m−n)θ}]——相位差里只剩 m−n。

【算一算】二维旋转与相对性，全部手算

取 q = k = (1, 0)，θ = 60°。先算各位置的旋转结果 R(mθ)q = (cos mθ, sin mθ)：

位置 m 旋转角 mθ R(mθ)q
00°(1, 0)
160°(0.5, 0.866)
2120°(−0.5, 0.866)
3180°(−1, 0)
4240°(−0.5, −0.866)

再算两组位置的内积，验证"只依赖差值 Δ = n − m"：

(m, n) Δ ⟨R(mθ)q, R(nθ)k⟩ cos(Δ·60°) 相等？
(1, 2)10.5×(−0.5) + 0.866×0.866 = 0.5cos 60° = 0.5✓
(3, 4)1(−1)×(−0.5) + 0×(−0.866) = 0.5cos 60° = 0.5✓
(1, 3)20.5×(−1) + 0.866×0 = −0.5cos 120° = −0.5✓

(1,2) 和 (3,4) 的绝对位置不同、差值相同 → 内积相同；差值变 2 → 内积变 cos 120°。 "只依赖相对位置"不是推导的结论，是你刚亲手算出的事实。

📐 数学推导：从二维旋转到通项公式

§3.2 的"两行证"给了相对性；这里补齐另外两块拼图——旋转矩阵的显式展开与复数实现 （RoPE 原论文的官方语言），最后用一个"每位置转 0.5 rad"的数值例把公式焐热。

① 旋转矩阵展开。 二维向量 $(x_0, x_1)$ 旋转 $\theta$ 角，用旋转矩阵表示：

$$R_\theta = \begin{pmatrix} \cos\theta & -\sin\theta \\ \sin\theta & \cos\theta \end{pmatrix}, \qquad R_\theta\begin{pmatrix} x_0 \\ x_1 \end{pmatrix} = \begin{pmatrix} x_0' \\ x_1' \end{pmatrix}$$

逐坐标写开就是两行三角函数：

$$x_0' = x_0\cos\theta - x_1\sin\theta, \qquad x_1' = x_0\sin\theta + x_1\cos\theta$$

这两行就是 §4.2 逐元素实现 q⊙cos + rotate_half(q)⊙sin 的数学本体——rotate_half 干的 就是"把 x₁ 挪到 x₀ 的位置、并管好正负号"。

② 复数写法。 把 $(x_0, x_1)$ 看成复数 $z = x_0 + i\,x_1$，旋转就是乘 $e^{i\theta}$ （乘一个单位复数 = 转一个角度）。两行证的核心性质在复数域里是乘法规则的显然推论：

e^{−imθ} · e^{inθ} = e^{i(n−m)θ}          ←→          R(mθ)ᵀR(nθ) = R((n−m)θ)

③ 通项公式。 64 维头切成 32 对，第 i 对的旋转频率与位置 m 的角度：

$$\mathrm{freq}[i] = \theta_{\mathrm{base}}^{-2i/d}, \qquad \mathrm{angle}_m = m \cdot \mathrm{freq}[i]$$

（§3.3 的频率分层表，就是把这张公式代入 θ=1e6 的结果。）

④ 复数版实现（minimind 官方 model_minimind.py 的写法，与本课实数版数学等价）：

def precompute_freqs_cis(dim, end, theta):        # 名字里的 cis = cos + i·sin
    freqs = 1.0 / (theta ** (torch.arange(0, dim, 2)[: dim // 2].float() / dim))
    angles = torch.outer(torch.arange(end).float(), freqs)   # (end, dim/2) 角度矩阵
    return torch.polar(torch.ones_like(angles), angles)      # e^{i·angle}：纯相位旋转因子表

def apply_rotary_emb(xq, freqs_cis):              # xq: (B, T, n_heads, hd)
    xc = torch.view_as_complex(xq.float().reshape(*xq.shape[:-1], -1, 2))  # 64 维→32 个复数
    fc = freqs_cis.view(1, xc.shape[1], 1, xc.shape[-1])                   # 广播到 (B,T,nh,32)
    return torch.view_as_real(xc * fc).flatten(3).type_as(xq)  # 复数乘法=旋转，摊回 64 维实数
  • torch.polar(r, θ) 构造 $r \cdot e^{i\theta}$——幅度全是 1，这是一张纯相位表；
  • view_as_complex 把最后一维的 (实部, 虚部) 成对折成复数：64 维恰好折成 32 个复数 = 32 对表针（钟表类比：每对维度像一根指针，各有自己的转速）；
  • 复数乘法 $(x_0 + i x_1)(\cos\theta + i\sin\theta)$ 的实部/虚部正是 ① 的两行—— 复数版与 §4.1 的实数版实现同一个旋转，但维度配对约定不同：复数版把相邻两维折成 (实部,虚部)，实数版 rotate_half 按前半/后半配对——对同一输入，两者结果差一个固定的 维度重排（各自约定下数学本体完全一致）。官方选复数版因为代码更短；本课选实数版因为 每一步肉眼可查。
  • ⚠️ 复数 tensor 只是脚手架：torch.polar 产出 complex64，混合精度下要先 .float() 再折 复数、转回时 .type_as(xq)——与 08 章 RMSNorm"fp32 里算、原 dtype 里住"同一个习惯。

⑤ 数值例：θ = 0.5 rad/位置。 取真实感的频率 θ=0.5，q = k = (1, 0)（单位向量，旋转不 改变长度）。位置 m 的向量转到 $(\cos 0.5m,\ \sin 0.5m)$，套两角差公式：

$$\langle q_m, k_n\rangle = \cos(0.5m)\cos(0.5n) + \sin(0.5m)\sin(0.5n) = \cos\big(0.5\,(n-m)\big)$$

(m, n) n−m 内积 解读
(2, 2)0cos 0 = 1.0自己看自己，完全对齐
(2, 3)1cos 0.5 ≈ 0.878相邻位置
(5, 6)1cos 0.5 ≈ 0.878绝对位置不同、差值相同 → 分毫不差
(2, 8)6cos 3.0 ≈ −0.99隔 6 个位置，几乎反向

(2,3) 与 (5,6) 的内积都是 0.878——§3.2【算一算】用 θ=60° 验证过的性质，换成弧度频率再验 一遍。cos 曲线还顺手给了注意力一个内建先验：相邻高分、远离衰减，只随距离、不随绝对位置。

3.3 高维推广：32 对表针，频率分层

64 维的头不是二维的。RoPE 把它切成 32 对，每对独立做二维旋转，第 i 对的频率按几何级数 递减：

θ_i = θ^(−2i/d)        i = 0, 1, …, 31        （θ 即 rope_theta，官方 1e6；
                                                        脚本里的常量 THETA、§4.2 的 θ_base 是同一个数的三种写法）

【算一算】频率表本身

θ = 1e6、d = 64：

  • 第 0 对：θ_0 = 1e6⁰ = 1 —— 位置每 +1 转 1 弧度（最快）
  • 第 31 对：θ_31 = 1e6^(−62/64) = 10^(6×(−0.969)) = 10^(−5.81) ≈ 1.5×10⁻⁶ —— 平均约 65 万个位置才转 1 弧度（约 408 万个位置转完一整圈）

换 θ = 1e4：θ_31 = 10^(−3.88) ≈ 1.3×10⁻⁴。两种 θ 的最低频对相差 10^(−5.81+3.88) = 10^(−1.93) ≈ 87 倍 ≈ 两个数量级——这就是"θ 大让低频维转得慢一个数量级"的出处。

为什么频率要分层？ 类比钟表：秒针/分针/时针转速不同，看一眼三根针的相对角度就能唯一 确定"现在几点"——单看秒针不行（60 秒一圈，1 点和 13 点的秒针位置相同）。

【算一算】近处看高频、远处看低频

只取两对：高频对 θ=1（秒针）、低频对 θ=0.01（时针），看不同距离差 Δ 下各自的相位差：

Δ 高频对相位 Δ·1 低频对相位 Δ·0.01 谁能分辨？
3 vs 4（近）171.9° vs 229.2°，差 57°1.7° vs 2.3°，差 0.6°高频一眼分辨
3 vs 9（远）171.9° vs 155.7°，只差 16°（开始"绕圈"：Δ 与 Δ+6.28 相位完全相同）1.7° vs 5.2°，单调不缠绕低频仍可靠

高频对管近处（角度大、分辨锐利），低频对管远处（绕得慢、不缠绕）。32 对频率把 从相邻 token 到几万 token 的所有距离尺度全覆盖——每种距离都有专属的"表针"。

🔑 三条性质现在全部有了出处：① 正交——旋转矩阵天然正交，不破坏内容信息（设计约束）； ② 相对——§3.2 推导所得（设计目标）；③ 可计算——位置出现在函数自变量里而非查表 下标里，任意位置代入即可求值（副产物，长上下文的入口）。

3.4 θ 深挖：一个数字，定住推理上限

rope_theta 是全模型最"便宜"的超参——一个数字，但它直接决定长距离行为。θ 大 → 低频维 转得更慢 → 同样长度内低频维的相位分布更"平缓"：训练长度内各位置的低频相位几乎不重复， 留给更长序列的"未缠绕区间"。配置上敢把 max_position_embeddings 写到 32768，靠的是 角度表能现算到任意长——但"能算"≠"算得好"（读数三、12 章实测），大倍数外推仍需缩放方案 ——而训练实际只用 340 个位置。🔑 训练长度与推理上限是解耦的：角度表是确定性函数现算 的，不参与训练。

两个实现细节（对应脚本写法）：

cos, sin = precompute_cos_sin(self.hd, max_pos, theta)
self.register_buffer('rope_cos', cos, persistent=False)
#                          ↑ persistent=False：不存进权重文件——表是现算的，存了反而浪费
#  对比 learned PE：pos_emb 是 nn.Parameter，0.52M 参数要训练、要保存
  • 📝 RoPE 没有任何可学习参数——08 章参数账本里它一行都不占（learned PE 的 pos_emb 0.52M 行因此消失，28.98M → 28.46M，§4.3 表退役）；② buffer 不是 Parameter，不进优化器、 不进 state_dict——"表"与"权重"的界限在代码层面就是这两个类的区别。

4.1 角度表预计算

def precompute_cos_sin(head_dim, max_seq_len, theta):
    inv_freq = 1.0 / (theta ** (torch.arange(0, head_dim, 2).float() / head_dim))
    # arange(0, 64, 2) = [0,2,4,…,62]：只取偶数下标——频率按"对"分配，64 维共 32 对（§3.3）
    angles = torch.outer(torch.arange(max_seq_len).float(), inv_freq)
    # 外积：(max_pos, 1) × (1, 32) → (max_pos, 32)。第 m 行第 i 列 = m·θ_i
    cos = torch.cat([torch.cos(angles), torch.cos(angles)], dim=-1)   # 32 → 64：每列存两份
    sin = torch.cat([torch.sin(angles), torch.sin(angles)], dim=-1)

4.2 rotate_half：为什么"拼两份"是对的

def rotate_half(x):
    half = x.shape[-1] // 2
    return torch.cat((-x[..., half:], x[..., :half]), dim=-1)   # (x1, x2) → (−x2, x1)

【算一算】拼接技巧 = 逐对旋转，并验证模长不变

取 4 维头（2 对）、q = (1, 2, 3, 4)，位置角：第 0 对 60°（c=0.5, s=0.866）、第 1 对 30°（c=0.866, s=0.5）。注意配对是 (q[0], q[2])、(q[1], q[3])——前半与后半配对。

按逐对旋转公式 x' = x·c − y·s, y' = y·c + x·s：

  • 第 0 对 (1, 3)：→ (1×0.5 − 3×0.866, 3×0.5 + 1×0.866) = (−2.098, 2.366)
  • 第 1 对 (2, 4)：→ (2×0.866 − 4×0.5, 4×0.866 + 2×0.5) = (−0.268, 4.464)
  • 拼回：q' = (−2.098, −0.268, 2.366, 4.464)

再用脚本的逐元素写法验证（cos 拼两份、rotate_half 取负对调）： q⊙cos + rotate_half(q)⊙sin，其中 rotate_half(q) = (−3, −4, 1, 2)：

  • q'[0] = 1×0.5 + (−3)×0.866 = −2.098 ✓
  • q'[1] = 2×0.866 + (−4)×0.5 = −0.268 ✓
  • q'[2] = 3×0.5 + 1×0.866 = 2.366 ✓
  • q'[3] = 4×0.866 + 2×0.5 = 4.464 ✓

两种算法逐位相等——一维逐元素乘加替代 32 个小矩阵乘。模长验证：|q|² = 1+4+9+16 = 30，

|q'|² = 4.40 + 0.07 + 5.60 + 19.93 = 30.0 ✓ 旋转正交、不破坏内容（性质①）。

4.3 Attention 类：本章的全部改动

class Attention(nn.Module):
    def __init__(self, hidden, n_heads, pos='learned', max_pos=MAX_POS, theta=THETA):
        super().__init__()
        self.pos = pos
        self.n_heads, self.hd = n_heads, hidden // n_heads
        self.q_proj = nn.Linear(hidden, hidden, bias=False)   # 与 02 章完全相同的四根投影
        self.k_proj = nn.Linear(hidden, hidden, bias=False)
        self.v_proj = nn.Linear(hidden, hidden, bias=False)
        self.o_proj = nn.Linear(hidden, hidden, bias=False)
        if pos == 'rope':                                     # 本章唯一的构造期变化
            cos, sin = precompute_cos_sin(self.hd, max_pos, theta)
            self.register_buffer('rope_cos', cos, persistent=False)
            self.register_buffer('rope_sin', sin, persistent=False)

    def forward(self, x):
        B, T, _ = x.shape
        q = self.q_proj(x).view(B, T, self.n_heads, self.hd)
        k = self.k_proj(x).view(B, T, self.n_heads, self.hd)
        v = self.v_proj(x).view(B, T, self.n_heads, self.hd)
        if self.pos == 'rope':                                # 本章唯一的 forward 变化
            cos = self.rope_cos[:T].unsqueeze(0).unsqueeze(2) # (1,T,1,hd) 广播到 batch 和头
            sin = self.rope_sin[:T].unsqueeze(0).unsqueeze(2)
            q = q * cos + rotate_half(q) * sin                # 位置旋进 q
            k = k * cos + rotate_half(k) * sin                # 位置旋进 k
        q, k, v = (t.transpose(1, 2) for t in (q, k, v))
        scores = (q @ k.transpose(-2, -1)) / math.sqrt(self.hd)
        scores = scores + torch.triu(torch.full((T, T), float('-inf'),
                                            device=x.device), 1)
        out = F.softmax(scores.float(), dim=-1).type_as(q) @ v
        return self.o_proj(out.transpose(1, 2).reshape(B, T, -1))

模型侧同步一处：pos_emb = ... if pos == 'learned' else None——表退役。

📝 q、k 必须共用同一张表：§3.2 推导 R(mθ)ᵀR(nθ)=R((n−m)θ) 的前提是两边的 θ 序列相同 ——任何一边用了不同角度来源，两行推导就不成立。

💡 与 02 章的代码差异只有四处（构造期签名与建表、forward 旋转分支、模型侧条件化）——读完 本章的完整故事后，可自行对照 02_baseline.py 复习旧写法。

5. 实验验证：learned PE vs RoPE，训练长度之外见真章

假设：learned PE 超出训练长度的位置没学过，应当出问题；RoPE 是函数，应当稳。 设置：同 seed、同数据（2 万条、seq=340）、同 300 步，只差 pos 一个开关。外推评估集 是专挑的长文本（150 条、全部长于 340、pad 补齐到 512，补齐位 label=-100 不进 loss）：

python 05_rope.py    # 约 4 分钟；实验②③在 06_gqa_qknorm.py

实测（RTX 4090，2026-09）：

位置编码ppl@340(训练长内)ppl@512(外推)
learned416.31430.60← 外推 +3.4%
rope333.88319.27← 外推 -4.4%（噪声内纹丝不动）

读数一：RoPE 连训练长度内都更低（334 vs 416）。 方向与 RoPE 论文一致——相对编码不用在 每个绝对位置重复学（§3.1 毛病二的直接验证）。实验素养：正式结论要跑 3-5 个种子取均值； 这里的核心是两个模型外推行为的相对关系，它跨种子稳定。

读数二：learned 只"钝痛"、没"猝死"，为什么？ 预期"外推该崩"，实际只退化 3.4%。机理： 未训练的位置行 ≈ normal(0, 0.02) 的初始化噪声 ≈ 接近零向量。加上一个近零向量 ≠ 加上 垃圾值——远处的 token 只是丢失位置信息（注意力退化成近似词袋），不被投毒。钝痛的 本质是"信息缺失"而非"信息污染"。

读数三：真正的硬上限在表长，不在质量。 max_pos 之外连查表都没得查（02 章脚本 generate 的滑窗行：生成时窗口逐 token 右移重算）。RoPE 的表是现算的函数——想要 32768 就现算 32768 行。"查表"和"求函数"的 差别，就是"有界视野"和"定义域可扩"的差别。📝 我们的外推只到 512（评估集文本长度所限）； 更大倍数（4×、16×）下 RoPE 也会退化——"能算"不等于"算得好"，见 §6。

🔬 实验是怎么搭的（把"假设"翻译成"测量"，完整翻译链条）：

理论主张 翻译成什么测量 在脚本哪里
"learned PE 超出训练长度会退化"构造长度上分布外的评估集build_extrap_eval：只收 SEQ+1=341 ≤ token 数 ≤ 510
"RoPE 的相对性使外推稳"同一批长文本上，两模型各测 ppl@512rope_vs_learned 的 for 循环
"差异只来自位置编码"同 seed、同数据、同步数、只差 pos 一个开关MiniMindForCausalLM(..., pos=pos)

测量陷阱：下界为什么是 341？短文本 pad 到 512 的话，pad 位在 labels 里是 -100 不进 交叉熵——实际被评估的仍是前 340 个位置，测量静默失效但数字看起来正常。控制变量的 现实粒度：train_model 开头重置 seed——数据采样顺序两模型完全一致；但 learned 多一个 pos_emb 初始化、多消耗几次随机数——初始权重并不相同。控制到"数据与训练路径严格一致、 模型各自随机初始化"，做消融时要声明控制到了哪一层。读数规则：ppl 绝对值无意义—— 跨模型比必须同评估集；跨长度比必须同模型（learned 自己的 +3.4%、rope 自己的 -4.4%）。

6. 讨论

论文：① RoFormer（Su et al. 2021，RoPE 原论文）——核心论证即 §3.2 的相对性推导；我们 的实验方向与论文一致，但 tiny 语料 + 温和倍数下差距远小于论文的长文本场景，复现论文结论先 对齐规模。② 长上下文缩放方案 PI（Position Interpolation，位置插值）/ NTK-aware（改 base 的外推 启发式）/ YaRN（Yet another RoPE extensioN）——RoPE"能算"之后"算得好"靠它们，加上不做 处理的 naive 共四件套，12 章有实测；§3.4 的 θ 深挖就是 NTK 变换的原理预热。③ ALiBi——不改向量、在注意力分数上减 距离惩罚，同为"相对"阵营但表达力上限低。

工业：① 训练长度是商业参数——API 报价的 128K/1M 上下文，背后第一战场就是位置编码 （RoPE + YaRN 或全参数长训）。② 位置编码本身零参数零缓存——这是它战胜 learned PE 的隐性 成本优势。③ 注意力"算得快"（FlashAttention 把 softmax 融进片上高速缓存 SRAM 里算）是 Part 9 CUDA 的主题；KV 怎么分页管理是 Part 14 vLLM 的核心。

面试直通车：

Q1: RoPE 相比可学习位置编码，好在哪两条？代价是什么？

A: ① 相对性：q·k 只依赖位置差（R(a)ᵀR(b)=R(b−a) 一行推完），模型不用在每个绝对位置重复学 同一种关系；② 可外推：位置是函数求值而非查表，训练外位置有定义（本课实测：learned 外推 +3.4% 退化且 max_pos 外连算都不能算，RoPE -4.4% 纹丝不动、表可现算到 32768）。代价：q/k 模长被旋转固定在输入上、尺度不受控——所以现代模型补了 QK-Norm（下一章）；且旋转逐维正交、 对与对之间无交互，表达力上限略低于学习式编码（实践中被更大 d 和数据补回）。

Q2: 为什么 rope_theta 大（1e6）比小（1e4）更耐长序列？

A: 第 i 对频率 θ^(-2i/d) 随 θ 增大整体变小，低频维转得慢 100 倍（§3.3 算例：1.3e-4 → 1.5e-6）。 低频维负责远距离分辨：转得慢意味着同样长度内相位不重复、不"多圈缠绕"。极端 θ→∞ 所有维都 不转等于没位置编码——θ 是"远距离分辨力 vs 近距离分辨力"的分配旋钮；YaRN 插值是在此之上的 精细再分配。

7. 小结

本章带走的三个结论：

  1. 注意力天生置换等变——不加位置信息就是词袋模型；learned PE 有"表长硬上限 + 绝对 位置"两个结构性毛病。
  2. RoPE = 给 q/k 乘旋转：R(a)ᵀR(b)=R(b−a) 一行推导送来相对性；32 对频率如钟表分层， 近处高频分辨、远处低频不缠绕；θ 一个数字定住推理上限（训练 340、现算 32768，解耦）。
  3. 实测：训练长内 rope 更好（334 vs 416），外推 rope 纹丝不动（-4.4% vs +3.4%）； learned 的退化是"信息缺失"式钝痛，真正的硬上限是表长本身。"能算"靠函数定义域， "算得好"要靠插值（PI/NTK/YaRN）。

下一章把注意力剩下的两笔账结清：推理时 KV Cache 的显存账（GQA）与训练中 q/k 范数漂移的 稳定账（QK-Norm）——脚本 06_gqa_qknorm.py 里 Attention 将再长出五处代码。

8. 习题

复述档（检验理解）：

1. 为什么说没有位置编码的 Transformer 是"词袋模型"？用两行说明。

注意力的输出是对全序列 v 的加权求和，权重 α 由内容点积决定，与位置无关；打乱输入顺序， 输出做同样的同序打乱（置换等变）。所以"猫咬狗"和"狗咬猫"的每个输出向量完全相同——只认 词集合、不认顺序。

2. "训练长度与推理上限解耦"是什么意思？靠哪两行代码实现？

训练只用 340 个位置，但推理时位置可以是函数定义域内的任何值（官方现算到 32768）——因为 位置由函数求值而非查表。实现：① precompute_cos_sin 按 max_pos 现算角度表；② register_buffer(..., persistent=False)——表不进权重文件，也不参与训练。对比 learned PE： 表只有 max_pos 行、每行都要训练，超表长连查都没得查。

计算档（检验会不会算，先自己算再看答案）：

3. q = k = (0, 1)，θ = 90°。写出位置 m=0..3 的旋转结果；再算 (m,n)=(0,2) 与 (2,4) 两组内积，验证只依赖 Δ=2。

R(0°)q=(0,1)；R(90°)q=(−1,0)；R(180°)q=(0,−1)；R(270°)q=(1,0)。 (m,n)=(0,2)：⟨(0,1),(0,−1)⟩ = −1；(m,n)=(2,4)：⟨(0,−1),(0,1)⟩ = −1。两组相等 ✓， 且等于 cos(Δ·90°) = cos 180° = −1。

4. θ = 1e6、d = 64。算第 0 对与第 31 对的频率，并回答：第 31 对要多少个位置差才 转完一圈？

第 0 对：θ_0 = 1e6⁰ = 1（每 +1 转 1 弧度）。第 31 对：θ_31 = 1e6^(−62/64) = 10^(−5.81) ≈ 1.5×10⁻⁶。转一圈需 2π/θ_31 ≈ 4.1×10⁶ 个位置差——约 408 万 token 的距离才转完一圈（正文 §3.3 的 "65 万转 1 弧度"是同一件事的另一种说法）， 这正是"远处不缠绕"的来源。

5. q = (1, 0, 2, 0)（4 维头、2 对），两对角度都是 90°（c=0, s=1）。用逐对旋转 公式手算 RoPE 输出，并验证模长不变。

配对为 (q[0], q[2]) = (1, 2) 与 (q[1], q[3]) = (0, 0)。 第 0 对：x' = 1×0 − 2×1 = −2；y' = 2×0 + 1×1 = 1。第 1 对：(0, 0) 旋转不变。

输出 q' = (−2, 0, 1, 0)。模长：|q|² = 1+0+4+0 = 5；|q'|² = 4+0+1+0 = 5 ✓。

动手档（检验能不能用）：

6. 把 <code>05_rope.py</code> 顶部的 THETA 从 1e6 改成 1e4，重跑实验①。 rope 的 ppl@512 会怎么变？为什么？

预期：rope 的 ppl@340 基本不变（近距离高频对相同），ppl@512 变差或波动更大——低频维转快 87 倍后，340~512 这段"训练外区间"的低频相位更早进入缠绕区。注意 learned 侧完全不受影响 （它不用角度表）；跑完对照 §5 的表格记录三个数字。这正是 §3.4"θ 是远/近分辨力的分配旋钮" 的直接实验。

7. 写 10 行以内脚本验证"q、k 必须共用同一张表"：k 换一张 θ=1e4 的角度表旋转后， 内积还只依赖 Δ 吗？

做法：precompute_cos_sin(16, 512, 1e6) 得 q 用的表，precompute_cos_sin(16, 512, 1e4) 得 k 用的表；随机 q、k，固定 m，扫不同的 n，检查内积是否仍是 n−m 的函数。（提示：模块名以 数字开头不能 import 05_rope——用 importlib.util.spec_from_file_location 加载，或把 precompute_cos_sin 函数直接复制进你的脚本。）结论：不是——内积里 混入了 m·(θ_q 对) 与 n·(θ_k 对) 的交叉项，只依赖差值的性质消失。这就是 §4.3 📝 的实验版。
