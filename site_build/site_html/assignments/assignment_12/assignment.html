Assignment 12：微调实战（LLaMA-Factory）

对应 Part 12 教程（01 手写管线 / 02 工作流）。 核心四道题全部纸笔/纯 Python 可完成；🌟 题 5 为 stretch 加分（torch 实现，可选，未实现返回 None 时测试自动 SKIP ⏭️）；实验题跑 02 章的工具链。

题目（实现 finetune_exercises.py 后 python test_finetune_exercises.py）

题 内容 分值
1LoRA 参数账：算可训练参数 Σ r·(out+in) 及占全参比例25 分
2合并数学：W' = W + (α/r)·B@A，并验证"合并前后前向一致"25 分
3B 零初始化：证明 B=0 时起点 ΔW=0（Frobenius 范数）——"起点无损"的数学表述25 分
4QLoRA 显存账：底座量化存储（params × bits/8）+ 可训练部分（×12B/参数）25 分
5 🌟多 rank 对比实验（stretch，torch 实现）加分 20 分，不计入基础分

计分口径：核心 4 题 25×4 = 100 分；🌟 题 5 为 stretch 加分项（+20 分，不计入 100 分基础分，单独记录）。题 5 未实现返回 None 时测试优雅 SKIP ⏭️，不影响任何得分。

题 1：LoRA 参数账（25 分）

给定被注入层 dims，算可训练参数 Σ r·(out+in) 及占全参比例——02 章 yaml 里 lora_rank 一个数字到底买了多少参数，这题就是它的公式。

验收标准：

  • [ ] lora_params([(288, 96), (96, 288)], 4) == 3072（精确整数，非近似）
  • [ ] lora_ratio(...) = 参数量 / base_params（返回浮点比例）
  • [ ] 纯 Python 完成（不需要 torch）

题 2：合并数学（25 分）

W' = W + (α/r)·B@A，并验证"合并前后前向输出一致"（merge 的正确性）—— 这是 01 章 merge_lora() / llamafactory-cli export 背后的全部数学。

验收标准：

  • [ ] merged_weight 返回 (out, in) 张量，不原地修改 W
  • [ ] 与 W + (α/r)·B@A 逐元素 allclose（atol=1e-6）
  • [ ] merge_changes_output 对随机 W/A/B/x 返回 True（合并前后 Wx+(α/r)·BAx 与 W'x 一致）

题 3：B 零初始化的意义（25 分）

证明 B=0 时起点 ΔW=0（Frobenius 范数）——"起点无损"的数学表述。

验收标准：

  • [ ] initial_delta_norm(A, torch.zeros(8, 4)) < 1e-9
  • [ ] 返回 float（Frobenius 范数 = 元素平方和开根）
  • [ ] 对非零 B 返回正确的范数（不是恒返回 0）

题 4：QLoRA 显存账（25 分）

底座量化存储（params × bits/8）+ 可训练部分（×12B/参数：bf16 参数与梯度 2+2B + fp32 AdamW 一阶/二阶动量 4+4B；LoRA 口径只算可训练参数）。 这是"QLoRA 7B 为什么 6GB 能跑"的粗估公式——静态账 ≈3.74GB；与官方 ~6GB 之间 ~2.26GB 的差 = 量化常数 + 激活 + CUDA context + 峰值波动（02 章 §3 有架桥）。

验收标准：

  • [ ] qlora_vram_gb(7.0, 4, 20_000_000) ≈ 3.74（相对误差 < 1e-9）
  • [ ] 单位换算正确：参数量 × 字节数 / 1e9 得 GB
  • [ ] 可训练部分用 12 字节/参数口径（bf16 参数+梯度 2+2B + fp32 双动量 4+4B；呼应 Part 10 的优化器账本）

题 5：🌟 多 rank 对比实验（stretch，加分 20 分，不计入 100）

冻结底座 W，真实权重更新是秩 4 的固定矩阵 ΔW\=B\@A\；对 r ∈ {1,2,4,8} 各注入一个 A(高斯)/B(零) 旁路，Adam 只训 A/B，对比起点/终点 loss——r ≥ 4 能完整表达 ΔW\（loss → 0）， r < 4 只能学到最优低秩近似（loss 卡在更高的平台）。这题用实验回答"lora_rank 该开多大"。

验收标准：

  • [ ] 返回 dict，keys 恰为 ranks=(1, 2, 4, 8)
  • [ ] params[r] == r·(out_f+in_f)（精确整数，呼应题 1 公式）
  • [ ] 各 r 的 loss_start 相同（B=0 ⇒ 起点输出即纯底座，与 r 无关）
  • [ ] 每个 r 的 loss_end < loss_start（任意 rank ≥ 1 都能学到一点）
  • [ ] r=8 的 loss_end ≤ r=1 的（rank 越大表达力越强）
  • [ ] r=4（≥ 目标秩）的 loss_end < 0.1 × loss_start（足够大的 rank 学到近零）

步骤提示（骨架 docstring 里有完整 Steps）：前向 Yh = X@W.T + (α/r)·(X@A.T)@B.T， F.mse_loss(Yh, Y)，Adam 300 步、lr=5e-2 即可（参考实现 ~0.5 秒跑完 4 个 rank）。 未实现返回 None → 测试 SKIP ⏭️，不扣分。

实验题（观测型，写 3-5 行结论进面经）

  • 跑 02 章工具链：QLoRA 7B × identity 数据集，记录显存曲线（对照官方 6GB 数字）
  • lora_rank 8 → 64：记录可训练参数比例与显存变化（呼应题 1 的公式）

🤔 思考题

Q1： LoRA 省的到底是什么显存？底座权重还要不要常驻？

💡 参考答案

省的是可训练参数的梯度和优化器状态：混合精度训练下每个可训练参数要付 bf16 参数+梯度（2+2B）+ fp32 一阶/二阶动量（4+4B）≈ 12 字节/参数 （若另计 fp32 master 权重副本再 +4B，即 16B/参数口径——7B 全参 ≈112GB+激活 ≈120GB）。 LoRA r=8 只训约 20M 参数，这部分 20M×12B ≈ 0.24GB < 1GB。但底座 W 必须全程常驻 （bf16 ≈ 14GB，QLoRA 4bit ≈ 3.5GB）—— LoRA 省的是"动量账"，不是"底座账"（正是题 4 公式的两项来源）。

Q2： 为什么 B 初始化为 0，而 A 不能也是 0？

💡 参考答案

B=0 保证训练起点 ΔW = BA = 0，不破坏预训练权重（题 3 的 Frobenius 范数为 0 即其数学表述）。 但 ∂L/∂B 依赖于 A、∂L/∂A 依赖于 B——若 A 也为 0，两个梯度同时为 0，参数永远不动 （一个死鞍点）。"高斯 A + 零 B"是同时满足"起点无损"和"梯度非零"的最简单组合。

Q3： 合并后为什么推理零开销？有没有不该合并的场景？

💡 参考答案

W' = W + (α/r)·BA 是精确加法：合并后前向从 Wx + (α/r)·BAx（两次矩阵乘）变成

W'x（一次），数学上逐元素相等——01 章脚本实测合并前后 max|Δlogits| ≤ 2.4e-06 （纯浮点舍入，脚本断言阈值 1e-4）。不该合并的场景：一份底座要服务多个任务/租户、 动态挂不同 adapter（如 vLLM multi-LoRA）——合并就失去了"共享底座 + 热插拔"的意义。

Q4： QLoRA 的 "Q" 量化的是哪部分？LoRA 的 A/B 也被量化吗？

💡 参考答案

只量化冻结底座（NF4 + 双重量化，0.5 字节/参数）；LoRA 的 A/B 以及 lm_head 等 可训练部分保持 bf16/fp32 高精度，反传时对量化权重做反量化计算。若把 A/B 也量化， 低精度的梯度更新基本学不动——这正是题 4 公式"底座 × bits/8 + 可训练 × 12B"两口径不同的原因。

Q5： lora_rank 从 4 提到 64，什么时候值得？代价是什么？

💡 参考答案

每层参数量随 r 线性增长（r·(out+in)）。值得加大的场景：任务与预训练分布差距大、 数据量大（几十万条以上）、或要学"新知识"而不只是"新格式"。代价：优化器状态与梯度线性 上涨、小数据上过拟合风险上升。题 5 的实验给出判据——若目标更新本身是低秩的（秩 4 的 目标用 r=4 就把 loss 打到近零），再加 r 只加参数不加效果。实践：从小 r 起步做基线， 效果卡住再加倍。

🎯 面试直通车（话术卡：结论 → 原理 → 边界）

每张卡按"总分总"组织：先一句话结论压场，再两三句原理支撑，最后一句边界/代价收尾——面试答题的固定骨架。

Q1："LoRA 到底省的什么显存？底座还要常驻吗？"

  • 结论：省的是"动量账"——只训 A/B 这约 20M 参数，梯度加 AdamW 状态按约 12 字节/参数算只要约 0.24GB；底座 W 该常驻还是要全程常驻。
  • 原理：混合精度训练下每个可训练参数付 bf16 参数+梯度（2+2B）加 fp32 双动量（4+4B）≈ 12 字节；7B 底座 LoRA r=8 只训约 20M 参数（占 0.3%），这笔账不到 1GB。但底座必须全程常驻——bf16 约 14GB，QLoRA 4bit 约 3.5GB，所以 LoRA 省的是可训练部分的梯度+优化器，不是底座账。
  • 边界：rank 拉大可训练参数按 $\sum r \cdot (\mathrm{out} + \mathrm{in})$ 线性涨，省的比例随之缩小；真正的大头永远是底座 dtype。

Q2："QLoRA 的 Q 量化的是哪部分？双量化能省多少？"

  • 结论：只量化冻结底座——NF4、双重量化、分页优化器三件套；其中双量化要在 65B 量级才省约 3GB，7B 上别拿它当卖点。
  • 原理：底座 4bit NF4 存储（$7 \times 10^9 \times 0.5$ 字节 ≈ 3.5GB），双重量化把量化常数再量化一遍、分页优化器在动量爆显存时先挪 CPU 兜底；LoRA 的 A/B 与 lm_head 保持高精度训练，反传时对量化权重反量化。课程静态账 ≈3.74GB（底座 3.5GB + 可训练 20M×12B ≈ 0.24GB），与官方 ~6GB 之间约 2.26GB 的差是量化常数+激活+CUDA context+峰值波动。
  • 边界：双量化收益与模型规模成正比（65B 才 ~3GB，7B 上是零头）；A/B 若也被量化，低精度梯度基本学不动。

Q3："LoRA 合并后为什么推理零开销？什么场景不该合并？"

  • 结论：合并是精确加法 $W' = W + (\alpha/r)\,B@A$，把两次矩阵乘换成一次且逐元素相等，所以零额外开销。
  • 原理：前向从 $Wx + (\alpha/r)\,BAx$ 变成 $W'x$，数学恒等——课程脚本逐 prompt 比对合并前后 logits，max|Δlogits| ≤ 2.4e-06（纯浮点舍入，断言阈值 1e-4）；这正是 llamafactory-cli export 背后的全部数学。
  • 边界：一份底座要服务多任务/多租户、动态挂不同 adapter（vLLM multi-LoRA）时不要合并——合并就失去了"共享底座 + 热插拔"。

Q4："为什么 B 初始化为 0？A 为什么不能也是 0？"

  • 结论：B=0 保证训练起点 $\Delta W = BA = 0$、不破坏预训练权重；A 若也是 0，两个梯度同时为 0，参数永远不动。
  • 原理：B=0 时起点 $\lVert \Delta W \rVert_F = 0$（Frobenius 范数就是"起点无损"的数学表述）；而 $\partial L/\partial B$ 依赖 A、$\partial L/\partial A$ 依赖 B，双零是一个死鞍点——"高斯 A + 零 B"是同时满足起点无损和梯度非零的最简组合。
  • 边界：这只保证起点等价，不保证学得动——目标更新秩高于 r 时只能学到最优低秩近似，loss 卡在更高的平台。

Q5："lora_rank 该开多大？"

  • 结论：从小 r（8/16）起步做基线再按需加倍——rank 的本质是给权重更新 $\Delta W$ 的秩上预算，够表达目标更新就行。
  • 原理：可训练参数随 r 线性增长（$\sum r \cdot (\mathrm{out} + \mathrm{in})$）；课程 rank 对比实验里目标更新本身就是秩 4 的 $\Delta W^\*$，r=4 就把终点 loss 打到起点的 10% 以下，r<4 只能学到低秩近似、卡在更高平台——r 一旦 ≥ 目标秩，再加只加参数不加效果。
  • 边界：任务与预训练分布差距大、数据量大（几十万条以上）或要学新知识时才值得加 r；代价是优化器状态线性上涨、小数据上过拟合风险上升。
