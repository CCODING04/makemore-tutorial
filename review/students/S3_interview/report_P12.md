## 白板默写自测（如实记录，不翻材料先写再对）

1. **LoRA 为什么低秩有效**：能完整默写——设计前提是预训练过参数化使"权重更新 ΔW 具有低内在秩"（Aghajanyan et al. 2020，LoRA 论文继承），r ≪ min(d,k) 时参数从 d×k 降到 r·(d+k)；d=k=4096、r=8 压缩 256 倍（复算 ✅）；toy 实证 3.1% 可训练参数即可学任务。**α 与 r**：scaling=α/r，作用是让 r 变化时"有效学习强度"可比（ΔW 幅度不随 r 漂移），常见 α=2r；对"为什么这个特定补偿形式"只能讲个大概（初始化方差与秩的关系），中等。
2. **QLoRA 三件套**：NF4 ✅——按权重正态分布的信息论最优 4bit 网格（分位数量化），比均匀 INT4 在同 bit 下误差更小；双量化 ✅——把每 64 参数共享的 FP32 量化常数再量化为 8bit（+每 256 组一个 FP32 偏移），常数开销 0.5→0.127 bits/param，65B 省 ~3GB、7B 折算 ~0.33GB；**分页优化器**——教程零覆盖，靠论文知识默写：NVIDIA unified memory 把 AdamW 的动量状态在显存不足时页出到 host RAM，峰值 OOM 由"崩溃"变"换页降速"，代价是吞吐——这条不是教程给的，如实记为"教程外"。
3. **LoRA vs 全参**：能默写决策依据——(a) 学"新格式/风格/任务适配"（中小数据）选 LoRA，学"新知识/分布剧变"（几十万条以上）全参上限更高；(b) 显存账：7B 全参 ~112GB(+激活)≈120GB vs LoRA ~16GB vs QLoRA 静态 3.74GB/实测 ~6GB；(c) 需要多 adapter 热插拔（multi-tenant）必须保留 LoRA 不合并；(d) 经验：从小 r 起步做基线，卡住再加 r（作业 Q5 判据 + 题 5 低秩目标实验）。

## 面试资产清单

- **实测可复现**（我已复跑）：6,144/200,664=3.1% 可训练参数（r=4 玩具）；loss 3.572→0.076（400 步）；合并前后 max|Δlogits|=2.38e-06；脚本 CPU 2.4s 复跑。
- **三个公式**：参数账 Σr·(out+in)；合并 W'=W+(α/r)·BA；显存账 = 底座×bits/8 + 可训练×12B（全参混合精度 Adam 为 16B/param）。
- **三个答辩点**：B=0 保"起点无损"、A≠0 防死鞍点（∂L/∂B 依赖 A、∂L/∂A 依赖 B）；merge 是精确加法→零推理开销，不合并场景 = multi-LoRA 热插拔；QLoRA 的 Q 只量化冻结底座，A/B 保持 bf16，反传时反量化。
- **数字口径表**（修正后）：7B 全参 112GB+激活≈120GB；LoRA bf16 ≈15-16GB；QLoRA 静态 3.74GB、官方实测 ~6GB；NF4 常数 0.44→0.11GB（双量化省 0.33GB@7B、~3GB@65B）。
- **陷阱辩护话术**：被问"双量化省多少"——答"0.37 bits/parameter；65B 折 ~3GB，7B 折 ~0.3GB"，**不要**引用教程的"0.37GB/3.87GB"。
- **分页优化器话术**（教程外自学补齐）：Adam 状态走 unified memory，显存吃紧时页出到 CPU RAM，把 OOM 崩溃变成可控降速；省的是峰值风险，不是平均显存。
