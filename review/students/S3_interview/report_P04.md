## 白板默写自测（如实记录）

**① linear + tanh 一层反向 —— 写出，全程无卡顿。**
设 `z = x@W + b`，`h = tanh(z)`，上游梯度 `dh`：
- `dz = dh * (1 - h²)`（以输出 h 表达，缓存 h 即可，不用重算 tanh(z)）
- `dW = x.T @ dz`，`db = dz.sum(0)`，`dx = dz @ W.T`
矩阵乘反传两个分支各用一次转置，与教程 01 的 `dL/dA = dL/dC @ B^T` 一致。

**② CE 为什么合并后梯度是 (softmax − onehot) —— 写出。**
单样本 `L = −z_y + log Σ_j e^{z_j}`（log-sum-exp）。对 z_i 求导：第一项给 `−𝟙(i=y)`；第二项 `∂/∂z_i log Σ e^{z_j} = e^{z_i}/Σ e^{z_j} = softmax_i`。相加即 `softmax(z)_i − onehot_i`，再除 N 对应 mean。关键一句：**log-sum-exp 的导数恰好是 softmax 本身**，这就是融合算子省 8 步的原因。

**③ BN 反传两个分支直觉 —— 写出。**
`x̂=(x−μ)/√(σ²+ε)`，梯度从 x̂ 回到 x 走两条路：(a) **直接路**——x 变化直接改变自己那行 x̂，贡献 `n·dhpreact` 项；(b) **统计路**——x 进入 μ 和 σ²，间接影响**全 batch** 每一行的 x̂，贡献 `−Σ(dhpreact)` 与 `−n/(n−1)·x̂·Σ(dhpreact·x̂)` 两项。一句话：**"自己影响自己 + 自己通过统计量影响所有人"**，三项公式各归其位。这也直接推出面试 follow-up：BN 梯度依赖 batch 组成 → 训练/推理行为不一致的根源。

## 面试资产清单（冲刺直接背诵）

1. **BN 反传 30 秒版**：y=γx̂+β 直接过；x̂ 层两条路——"自己影响自己"（n·dhpreact 项）+"通过 μ、σ² 影响全 batch"（−Σdhpreact 与 −n/(n−1)·x̂·Σ(dhpreact·x̂) 项）；一行公式三项，背表即可。
2. **CE 梯度一句话**：log-sum-exp 的导数恰为 softmax → ∂L/∂z = (softmax − onehot)/N；三行代码 `softmax → 正确位减 1 → 除 N`。
3. **tanh 反传细节分**：用 `1 − h²` 以**输出**表达局部导数，缓存 h 免重算 tanh——自动求微分的"重算 vs 缓存"权衡实例。
4. **retain_grad/is_leaf**：非叶子张量 `.grad` 默认不保留（省内存），`retain_grad()` 显式开启——脚本 03 用 UserWarning 亲自演示的坑，讲 autograd 实现的差异化亮点。
5. **Bessel 校正**：无偏方差除 (n−1) → 简化公式出现 n/(n−1) 因子；PyTorch `var(unbiased=True)`；n 大时趋近 1。
6. **cmp() 对拍范式**：任何手写算子先用 autograd 当标准答案做 max diff 验证——自定义 op 开发的通用工程流程。
7. **锚点数字**：初始 loss ≈ 3.32（实测 3.3177）；12 步反传 vs autograd ≤ 5.59e-09；BN 简化公式 diff ≈ 4.56e-05（float32 正常现象，能主动讲出是加分项）；--quick 1000 步 train/dev ≈ 2.47/2.46。
8. **引申钩子**：BN 梯度依赖 batch 统计量 → 训练/推理不一致 → running stats 与 eval 模式（衔接 Part 3/Part 5）。
