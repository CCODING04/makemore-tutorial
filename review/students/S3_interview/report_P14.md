## 白板默写自测（先默写后对照，4/4 通过）

| 题 | 我的默写要点 | 对照结果 |
|---|---|---|
| TTFT/TPOT 定义与分母口径 | TTFT = 提交→首 token 到达的时刻差（无分母，prefill 主导）；TPOT = (t_last − t_first)/(n−1)，**分母 n−1 因首 token 已计入 TTFT**，除以 n 会系统性低估；E2E ≈ TTFT + TPOT×(n−1)；HF generate 一次性调用需 max_new_tokens=1 独立探测 + 同步 | ✅ 与 01 章 L83-88 完全一致，脚本口径（探测不入吞吐分母）也对上 |
| PagedAttention 解决什么问题 | KV cache 按 max_seq_len 整块连续预留 → 内部碎片（2048 预留 512 用，浪费 75%）+ 外部碎片 → 并发上不去。分页：固定 block（16 token/块）按需分配 + 块表映射，浪费只剩末块内碎片（论文口径 <4%）；不改 KV 公式任何系数，改"seq 的计量方式" → 并发数同比例上升 | ✅ 与 02 章推导 + assignment Q4 一致 |
| 连续批处理 vs 静态批处理 | 静态：攒批出发、pad 到最长、整批陪跑到最慢（100/10/10/10 → 浪费 67.5%）；但已比逐请求赢 ~7×（权重一次搬运喂 8 请求，memory-bound 摊薄）。连续（Orca）：iteration-level 调度，完成即腾位、新请求即刻补位，理想浪费 0；负载同质时收益主要来自补位而非提前释放 | ✅ 与 01 章、assignment 题 3 + 思考题 Q1 一致 |
| 投机解码接受率与加速比 | 每周期期望 E = 1+α+…+α^γ = (1−α^(γ+1))/(1−α)（等比级数；α=1 极限 γ+1；α=0 仍白赚 1）；加速比 = E/(1+draft_overhead)，上界 γ+1；α=0.6,γ=4 → 2.3056；负收益条件 = α 低 + draft 贵（0.667<1）；成立前提 decode memory-bound，验证 γ+1 位置权重只搬一遍；batch 大到 compute-bound 即失效 | ✅ 与 assignment 题 4 + 思考题 Q3 一致 |
