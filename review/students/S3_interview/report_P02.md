1. 【硬伤·数学错误】`02_mlp_architecture.md` L143：`emb.view(-1) → (64,)`。实测 `(32,3,2).view(-1)` = **(192,)**（32×3×2）。当场面推 shape 时照教程念会翻车。

4. 【缺失·真实数字锚点】教程全文没有给出本章模型的任何真实训练数字：没有初始 loss，没有训练后 train/dev/test loss，没有 dev-train gap。我实测（同 seed 同超参）：初始 batch loss ≈ **18~20**（randn 初始化），训练后 **TRAIN=2.3766 / DEV=2.3740 / TEST=2.3750**，gap≈-0.003。面试必问"你的模型 loss 多少"，教程无数字可背。

## 五、白板默写自测（不看书手推，随后对照教程与实测验证）

**1) MLP 前向 shape 链**（block_size=3, n_embd=2, n_hidden=100, N 个样本）

```
X        (N, 3)     字符索引
C       (27, 2)     嵌入表
C[X]     (N, 3, 2)  每个索引换成 C 的对应行
view     (N, 6)     3×2 拍平（-1 = 6N/N 自动算）
@W1+b1   (N, 100)   W1(6,100)
tanh     (N, 100)   压到 [-1,1]
@W2+b2   (N, 27)    logits, W2(100,27)
F.cross_entropy -> 标量（内部 log_softmax + NLL，先减 max 防溢出）
参数量 = 27·2 + 6·100 + 100 + 100·27 + 27 = 54+600+100+2700+27 = 3481 ✅ 与脚本 04 打印一致
```
自评：脱稿通过；`view(-1)` 那行教程写错成 64，我自己推的 192 才是对的。

**2) 为什么用 train/dev/test 三份**

- Train：拟合参数 θ，回答"模型能不能拟合数据"。
- Dev：模型选择/调超参/早停，回答"哪个配置泛化最好"。可以反复看，但每看一次就在 dev 上做了一次隐式选择，调得太多 dev 也会被"过拟合"。
- Test：无偏终评，回答"最终性能是多少"。只用一次，用了即失效。
- 一句话版：train 管拟合、dev 管选择、test 管汇报；信息从数据 → 参数（train 合法），信息从数据 → 超参（dev 半合法），test 必须零信息泄漏。

**3) "train=2.20 vs dev=2.47，过拟合还是欠拟合"的标准讲法（三层）**

1. 先看绝对值：均匀分布基线 ln(27)=3.296，bigram 基线 ≈2.45-2.48。dev=2.47 只追平 bigram，说明模型几乎没从 3 字符上下文里赚到钱——第一反应是**容量/训练不足（欠拟合方向）**，不是过拟合。真正的过拟合长什么样？train 掉到 1.x 而 dev 停在 2.x。
2. 再看差距显著性：dev 有 22655 个样本，loss 标准误约 ±0.02，0.27 的 gap 远超噪声，是真实的系统性差距，但幅度不算大。
3. 决定动作：先加容量（n_embd 2→10、hidden 100→200）看 dev——dev 跟着降 = 原来是欠拟合；dev 反升 = 才轮到正则/dropout/加数据。**切忌看到 gap 就喊过拟合**。本教程实测 train 2.3766 / dev 2.3740（gap≈0）正是"3481 参数 vs 18 万样本，欠拟合区"的活例子，印证 03 章"不太会过拟合"的声明。
4. 追问预案：为什么不用 test 判断？——test 只用一次，用在它上面做诊断就把它变成了第二个 dev。

**4) 面试钩子：嵌入梯度为什么稀疏（roadmap 要求，教程缺失，自查补课）**

- 前向 `C[X]` 是查表，等价 `F.one_hot(X,27) @ C`；反向对等价式求导：`dL/dC = Σ_sample onehot(x)ᵀ @ dL/d(emb)`——one-hot 的 0 把所有未出现行乘成 0，所以**每步只有 batch 中出现过的字符行收到非零梯度（scatter-add）**。
- 实测：`Xb=[[0,0,5],[0,5,13]]`，backward 后非零梯度行恰好 = {0,5,13}（scratch/test_hooks.py）。
- 面试延伸：batch=32、block=3 时每步最多 96 个"热行"，27 行的表全热，但大词表（如 5 万 token）时热行占比极小 → 这就是稀疏 embedding 更新、以及大模型训练里 optimizer 状态按行懒初始化的动机。少有人讲，讲出来是论文级细节。
