## 白板默写自测（不查资料先写，再对卷）

1. **contextual retrieval 解决什么问题（一句话）**：✅ 写出——"chunk 一旦切出就脱离原文语境（断章取义），孤立表格/片段嵌不进任何查询语义；在嵌入前给每块拼一段 LLM 生成的全文定位句，把文档级语境还给块。"
   **数字链讲法**：✅ 写出——官方失败率 5.7%（纯嵌入）→ 3.7%（+上下文）→ 2.9%（+BM25 混合）→ 1.9%（+rerank），累计 -67%，248M chunk 语料；本机 recall@20 不升反缓降（0.67→0.61），四条归因：0.5B vs Claude 的定位句质量、8 篇 vs 248M 的语料规模、失败率 vs recall 的指标口径、前缀抬 df 稀释 BM25。
2. **late chunking 与 contextual retrieval 的区别**：✅ 写出——"contextual retrieval 先切后补：改的是送进嵌入模型的文本，每块一次 LLM 调用，任意嵌入模型可用；late chunking 先嵌后切：长上下文嵌入模型整篇编码成 token 向量序列，再按边界切、逐块池化，零 LLM 调用但绑定模型家族。一句话：给块补上下文 vs 让上下文先于切块发生。"
3. **faithfulness 手写**：✅ 写出——"answer 拆原子 claims → 逐条构造（contexts + 当前 claim）的 entailment prompt 调 judge → 解析 yes/no/unsure，yes 计 1、no 与 unsure 计 0（保守口径，文档化）→ 支持数/总 claims；空答案返回 None；judge 是可调用对象，可注入 mock 离线测试。" 追问"unsure 计 0 vs 剔除分母"也能答（计 0 防虚高但把检索的锅记到生成头上；剔除则含糊其辞成法外之地；折中是三数齐报）。
4. **写不出/不熟的**：如实记——① GraphRAG 的社区摘要层级（community→全局查询）只能讲方向，层细节默写不出；② Kendall τ 与 AP 的公式我只能讲直觉不能白板推；③ 自测中发现我把"1.02 美元/百万 token"背成了泛化口径，对卷后才确认精确口径是"每百万**文档** token"。
