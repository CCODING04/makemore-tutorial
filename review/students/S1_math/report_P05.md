## 费曼自检（先自答，再核对教程/实验）

**1. 为什么 3D BatchNorm 必须在 dim=(0,1) 上归一化，而不是只 dim=0？**
自答：BN 的目的是"每个通道一套统计量"。若只对 batch 维 reduce，得到 (1,T,C)——同一个字符 embedding 的同一通道，在位置 0 和位置 4 会被**不同的均值/方差**缩放；同一个通道在不同时间步被拉扯成不同尺度，下游再 FC(2) 拼接时两半根本不可比。只有在 (0,1) 上一起 reduce，才保证"同一通道、同一把尺子"。
核对：与教程 03、06 脚本打印、作业题 3 思考题一致。**通过。**

**2. 放大 WaveNet 到底多少参数？**
自答（心算第一遍）：12,397 → 跑脚本得 22,397 → 重新手算 270+1,360+136+9,248+136+9,248+136+1,863 = 22,397 ✓（第一遍是加法错了）。
放大版：648 + 6,144+256 + 32,768+256 + 32,768+256 + 3,483 = **76,579**，脚本实测一致 → **教程 ~170K 错误**。
核对：教程 03 表格。**发现教程错误 1 处，小模型数字核对通过。**教训：心算必须用脚本兜底，教程数字也可能错。

**3. `torch.cat([x[:,::2,:], x[:,1::2,:]], dim=2)` 和 `x.view(B, T//2, C*2)` 相等吗？**
自答（第一反应）：不相等，我印象里"偶数位 + 奇数位"的拼法和 view 的内存顺序会不一样。
手推：`x[:,::2,:]` 是 t=0,2,4,6 压缩成第 0..3 行，`x[:,1::2,:]` 是 t=1,3,5,7；cat 后第 i 组 = [t_{2i}, t_{2i+1}]，与 view 的内存顺序**完全一致**。
核对：`torch.equal` 实测 `True`（用 arange 张量逐元素验证）。→ **我的第一直觉错了，脚本 04 的注释也错了，教程 02 的说法才是对的。**（教训：切片+cat 这类题必须动手验证，直觉和"印象里的视频"都靠不住。）

**4. BatchNorm 训练/推理差别，忘切模式会怎样？**
自答：训练用 batch 统计量并更新 running；eval 用 running 且冻结。忘切 eval → 输出随当前 batch 抖动、不确定性；忘切 train → running 永远停在初始值（若网络依赖 BN 的 normalize，推理统计量整个是 0/1 初值）。
核对：教程 01 表格一致；06 脚本的 Buggy 类就是"忘更新"的活例子（但脚本没把它讲破，见卡点 5）。**通过，且找到了教程没讲的后果。**
