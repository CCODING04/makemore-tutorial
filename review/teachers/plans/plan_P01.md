## 四、本 Part 特有审计要点

1. **NLL 推导可读性**（对应旧卡点 9 残留）：逐行检查 L196-209 推导块，确认每步"为什么"是否可由数学不强读者跟上；"取负"直觉已有，但缺"下溢"的具体数字示例，审计时验证。
2. **bigram 计数 ⇄ 神经网络等价性实测**：跑 05 与 07，核对 2.45（计数）vs 2.47（NN）数值一致性；重点核实：03 章 L171-176 声称对比 `W.exp()` 与 N，但计数版实际用了平滑 (N+1)，等价对象应是 (N+1) 归一化后的分布——教程未言明，属概念精度风险。
3. **Softmax 直觉**：`logits.exp()`"类比计数矩阵"的讲法是否足以让读者接受 exp 的来历（软-max 的"软"字从未出现，审计评估是否需一词点题）。
4. **示例输出一致性**：02 章 L172-180 采样输出自带版本差异免责声明，实测当前环境脚本 04 输出，确认免责声明仍必要/足够。
5. **作业思考题质量**：题 4"NLL 与 bit 编码"（超纲但面试向，评估是否给 details 提示）；题 5 `lr=50` 默认值与教程 L140-145 解释是否自洽；作业 README L42-46 文件结构自引用 `assignment.md`，实际文件为 `README.md`（描述 bug，审计列入整改项）。
6. **roadmap 承接核对**：环境自检节（C1-2）、ln(27) 锚点（C1-3）、论文跳转（C1-4）三项逐一定位整改落点。
7. **作业测试可跑性**：roadmap 验证标准 `pytest assignments/assignment_1/` 全绿——审计时实际执行（含 README 的 `python test_bigram_exercises.py` 方式）。
