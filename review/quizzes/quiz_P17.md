# 测验 · Part 17（Agentic RL：从单轮 RLVR 到多轮工具调用）

> 依据：本 Part 学习目标与教程正文。建议先完成作业再自测；每题附答案与教程锚点。

## 测验（5 题）

**Q1（概念）** 在多轮工具调用轨迹里，为什么观测（工具输出）token 的 loss-mask 必须为 0？整条轨迹只有一个 0/1 奖励，怎么分配到每个 token？

- **答案**：观测 mask=0 的三重理由：① 工具输出是环境生成的，不是模型的"话"；② 模型无法预测外部结果，算 loss 是浪费容量；③ 更糟——模型可能学会"生成自己期望的观测"（幻觉工具结果）。奖励分配（轨迹级 GRPO）：整条轨迹末尾一个奖励，组内标准化 $A=(r-\mathrm{mean})/\mathrm{std}$ 后**广播到该轨迹的全部 assistant token**（工具调用也要学——"学会调对工具"本身就是任务的一部分），loss $=-\sum \log\pi(\mathrm{token})\cdot A/\#\mathrm{assistant}$；观测 token 不参与。轨迹 mask 模式：user=0、assistant=1、观测=0。
- **锚点**：教程 01_from_single_turn_to_agent.md §1 多轮轨迹的解剖 + §3 轨迹级 GRPO：奖励怎么分配

**Q2（数字）** 掩码消融实验（同 seed=7，唯一变量 = 观测内容是否泄漏进策略输入）的四格数字各是多少？"消融的信号"应该看哪些格？随机初始化（无 BC）的开卷 train 又是多少？

- **答案**：A 组 mask=True：开卷 train 99.0% / 开卷 holdout 12.5% / 闭卷 train 43.8% / 闭卷 holdout 25.0%；B 组泄漏（mask=False）：96.9% / 3.1% / 10.4% / 0.0%。信号不在 train（泄漏组 96.9% 并不差），在 holdout 与闭卷：第二次观测本身就等于最终答案，泄漏组学到的最优解是"复读观测"，答案 token 从未被训练成计算的函数，组合一没见过或观测一拿走就现形；mask 组只能把 a×b+c 内化进参数，闭卷 train 仍保 43.8%。结论："开卷成绩好看 ≠ 学会了计算；泄漏买来的是依赖，不是能力"。另：随机初始化（无 BC）开卷 train 仅 10.4%。
- **锚点**：教程 01_from_single_turn_to_agent.md §4 实测：BC 冷启动 → RL → 掩码消融 + 性能数据表

**Q3（对比）** 四种奖励设计（稀疏结果 / ToolRL 式塑形 / ORM / 课程学习）各自的优劣是什么？防 reward hacking 的"四件套"防线有哪些？

- **答案**：稀疏结果奖励（Search-R1，只看最终答案对错）：简单、不可作弊，但 10+ 轮轨迹的 credit assignment 噪声大；过程/塑形奖励（ToolRL 把奖励分解为格式+参数+结果的细粒度）：信号密、收敛快，设计不当会引入偏差；ORM（训练奖励模型打分）：可泛化到难形式化任务，但 RM 可被 hack、有偏差；课程学习（WebRL 从失败任务再生任务）：与模型能力同步演进，系统复杂。防 hacking 四件套：调用去重、轮数上限+溢出惩罚、环境沙盒、轨迹抽样人工审查（Agentic 环境里可钻的空子远多于单轮——复读机式调用、回显 prompt、打印预期答案）。
- **锚点**：教程 02_rewards_and_frameworks.md §1 奖励设计谱系 + 常见陷阱：reward hacking

**Q4（诊断）** 实验中把 BC 示范从 6 个组合砍到 2 个，RL 六轮组平均奖励纹丝不动卡在 0.33。诊断死锁的完整链条与解法；为什么"BC 饱和后 RL 在训练组合上边际增益小"反而正常？

- **答案**：链条：示范覆盖不足 → 未见组合上采不出能拿分的轨迹 → 组内奖励全 0 → 组内 std=0 → GRPO 优势全零 → 无梯度 → 永远采不出（稀疏奖励死锁）。解法：BC 冷启动决定 RL 能否启动——覆盖度要够、策略熵要软（把 BC 步数调软到 40 步后，RL 把 0.33 推到 0.50）；工程上监控全零组占比、扩大示范覆盖/提高组大小/降低任务难度。R1 论文的 cold start SFT 解的就是这个问题。反过来，示范与 rollout 同构时 120 步 BC 已把开卷 train 拉到 99.0%，组内几乎全对 → std≈0 → 梯度≈0，RL 边际增益小是正常现象（真实任务分布大得多，BC 无法覆盖，RL 才有空间）。
- **锚点**：教程 01_from_single_turn_to_agent.md §4 三个必讲的观察①② + 02_rewards_and_frameworks.md §调试展示错误 1

**Q5（概念）** 什么是 Echo Trap？为什么奖励曲线看不出来？怎么发现和缓解？

- **答案**：多轮 RL 特有的稳定性陷阱（RAGEN 论文，2504.20073）：策略熵坍缩到重复模板——同样的工具调用循环往复。奖励曲线看不出来，因为模板可能还拿得到低分（学习看似在进行，探索已死）。发现：监控 rollout 熵与轨迹多样性（不同轨迹比例；作业的 echo_trap_score 用去重比例，但"多样但全错"说明还要联合看成功率与熵）。缓解：StarPO-S 三件套 = critic 辅助 + clip-higher（提高上界探索）+ rollout 过滤（丢弃零方差组）。其单轮版就是"全同组优势全零"——无区分度的组没有梯度。
- **锚点**：教程 01_from_single_turn_to_agent.md §错误 3：Echo Trap + 02_rewards_and_frameworks.md §2 稳定性：Echo Trap 与 StarPO-S

## 闪卡（正/背）

| 正面 | 背面 |
|---|---|
| 多轮轨迹 mask 模式 | user=0、assistant=1、观测=0：mask=[0,1,0,1,…]；Agentic 轨迹 assistant token 占比典型 10-30% |
| 轨迹级 GRPO | $A=(r-\mathrm{mean})/\mathrm{std}$ 组内标准化后广播到全部 assistant token；全同组 → 优势全零（eps 兜底不除零） |
| 掩码消融四格 | A（mask）99.0 / 12.5 / 43.8 / 25.0 vs B（泄漏）96.9 / 3.1 / 10.4 / 0.0（开卷 train / 开卷 holdout / 闭卷 train / 闭卷 holdout） |
| 冷启动实测数字 | 随机初始化开卷 10.4%；仅 BC（A）100.0/40.6/36.5/31.2；仅 BC（B）holdout 0.0——崩塌在 BC 阶段已注定；BC 砍到 2 组合 RL 卡 0.33，步数调软 40 → 0.50 |
| 两种 mask 别混淆 | loss mask（观测 token 不进 loss）≠ 内容遮蔽（观测换 <mask>）；工业实现（verl/slime）= 观测进上下文 + loss mask；共同原则：环境给的 token 不承载策略梯度 |
| 玩具判分漏洞 | 奖励取"最后出现的数字"→ 第二次观测冒充答案；真实 RLVR 堵法：格式约束（\boxed / ####）、判分只看 assistant 段、答案位置锚定（<eos> 前） |
| 解析失败死锁 | 工具调用解析失败 → 奖励恒 0；开训前用示范轨迹统计解析成功率（assert==1.0），协议一处改动全链路同步 |
| rollout 截断冤案 | 截断轨迹没有答案段、按 0 分判分与"答错"无关；区分"答错"与"没答完"，监控截断率，必要时 partial rollout |
| Echo Trap / StarPO-S | 熵坍缩到重复模板、奖励曲线看不出；监控熵+轨迹多样性；缓解 = critic + clip-higher + rollout 过滤 |
| 奖励类型谱系 | 稀疏结果（不可作弊但噪声大）/ ToolRL 塑形（格式+参数+结果，示例权重 0.2/0.3/0.5）/ ORM（可 hack）/ 课程学习（系统复杂） |
| 异步 rollout 的理由 | 轨迹长度重尾（Kimi-Researcher 平均 23 次工具调用/回答）；同步要等最长轨迹，异步让短轨迹先返回 |
| GiGPO | 在"锚定状态"（跨 episode 可匹配的相同状态）上建 step 级分组，细粒度 credit 且保持 critic-free |
| 零方差组处理 | 无区分度的组没有梯度；rollout 过滤丢弃 / 提高采样温度与多样性 / 更细粒度奖励分解 |
| 框架与评估选型 | verl（23.2k，multi-turn 最全）首选入门与生产 → slime / verl-agent 进阶；评估 τ-bench、GAIA L1 起步；全异步场景 SkyRL / AReaL |
