# 测验 · Part 13（数据工程：从手写 MinHash 到 Data-Juicer）

> 依据：本 Part 学习目标与教程正文。建议先完成作业再自测；每题附答案与教程锚点。

## 测验（5 题）

**Q1（概念）** 预训练语料有哪三类质量问题？MinHash 为什么能"哈希一下"就近似 Jaccard 相似度？写出它的核心概率等式。

- **答案**：三类问题：重复数据（C4 约 4.3% 是精确重复，模型"记住"而非"理解"）、低质量数据（垃圾/广告/机器生成）、污染数据（测试集泄露进训练集，评估失真）。MinHash 定义 $h(S)$ 为集合 S 在哈希函数 h 下的最小哈希值，核心等式是 $P[h(A) = h(B)] = J(A,B)$——并集中哈希最小的元素恰好落在交集里的概率等于 $\lvert A \cap B \rvert / \lvert A \cup B \rvert$。用 k 个独立哈希函数得签名向量，签名一致率是 Jaccard 的无偏估计（$\text{Var} = J(1-J)/k$）。实测：64 维签名一致率 0.69 ≈ 真实 Jaccard 0.73。
- **锚点**：教程 01_dedup_from_scratch.md §数学推导（MinHash 的概率性质）+ §代码实现（实测输出 [4]）+ README §理论背景

**Q2（数字）** 写出 Chinchilla 三项式并给出五个参数的拟合值。"20 t/p"到"1875 t/p"的演化逻辑是什么？Llama 3 为什么敢这么训？

- **答案**：$L(N, D) = E + A/N^{\alpha} + B/D^{\beta}$，Chinchilla 拟合值 E=1.69（不可约损失/数据条件熵下界）、A=406.4、α=0.34（容量项）、B=410.7、β=0.28（数据项）。t/p = D/N：Chinchilla 结论 ≈20 t/p（70B/1.4T），Llama 2-70B ≈29，Llama 3.1-8B 用 15T token 达 ≈1875 t/p（约 90 倍过训练）。逻辑链：Chinchilla 只最小化训练算力，而部署期推理成本与参数量成正比（每 token 约 2N FLOPs）——小模型+多数据在总成本上更便宜，inference-aware scaling 解出的 N 更小、D 更大。这也是数据工程在 2024 后更重要的原因：模型小了，数据配额放大几十倍。
- **锚点**：教程 00_scaling_laws.md §数学推导（第 3/6 步：Chinchilla 三项式 / 过训练时代）

**Q3（诊断）** epoch 实验（tiny shakespeare，6.10M 参数模型）：R=16 时 train loss 降到 0.9505，val loss 反而从 1.6988（R=8）升到 1.8849。诊断发生了什么？这给"去重删多少、重复几遍"什么结论？

- **答案**：train/val 分叉、val 反升（幂律外推 1.6073，实测偏离 +17.3%），说明模型在背语料而不是学语言——重复 token 的有效价值崩塌，实测 R=16 时 R_eff/R 折扣仅 0.39x。对照 Muennighoff 结论：R≤4 重复近似免费（实测贴幂律 ±3~7%），4<R≤16 边际收益递减，R>16 趋向于零。结论：与其把预算花在 R=16 的重复上，不如去重后换 4 倍 unique 数据；同时 scaling 实验必须用 held-out 验证 loss——训练 loss 反映的是背诵能力。
- **锚点**：教程 00_scaling_laws.md §实测（模式三：epoch）+ §常见陷阱（陷阱 3）

**Q4（对比）** FineWeb 用 14 band × 8 row、"等效阈值 ≈0.7"。这个阈值从哪来？若签名维度保持 112 但改成 28 band × 4 row，S 曲线拐点移到哪、召回和误报各怎么变？

- **答案**：LSH 候选概率 $P = 1 - (1 - J^r)^b$ 呈 S 曲线，拐点近似 $(1/b)^{1/r}$：14×8 时 $(1/14)^{1/8} \approx 0.72$——相似度高于它的对大概率成候选、低于的大概率被过滤（这就是"≈0.7"的来历）。改成 28×4 后拐点 $(1/28)^{1/4} \approx 0.44$：阈值左移，召回变高（更低相似度的对也被抓到）但误报变多、验证步工作量上升。b 升召回、r 升严格度，乘积受签名维度预算约束——b/r 是"召回-误报"同一枚硬币的两面。
- **锚点**：教程 01_dedup_from_scratch.md §数学推导（LSH 的分带机制）+ 作业 13 思考题 Q4

**Q5（概念）** 设计一条完整清洗管线：算子应按什么顺序排？LSH 候选对为什么必须再过一道 Jaccard 验证？重复簇里保留哪一篇——keep-first 有什么工业缺陷？

- **答案**：顺序是轻过滤 → 去重 → 重过滤/清洗（FineWeb 口径）：先用廉价启发式（语种/词数/符号比）砍掉明显垃圾，再做昂贵的 MinHash 去重（避免给垃圾也建签名），最后才上 LLM 质量打分等重算子，审计（逐 op 追踪报告）贯穿全程。验证步必需：LSH 的设计哲学是"高召回换误报"（实测候选 3 对、真重复只有 2 对，误报对真实 J=0.45 在阈值 0.5 之下），确定性靠 Jaccard 精算兜底——删掉验证步就会成批误删好文档。keep-first 的缺陷：重复簇里最靠前的未必质量最好（转载页常比原文更长更完整），工业上可用 keep-longest/带质量分的 keep-best。
- **锚点**：教程 02_data_juicer_pipeline.md §工程实践（陷阱 1 + 最佳实践管线设计原则）+ 01_dedup_from_scratch.md §代码实现（四个必须理解的点②）+ 作业 13 题 5
